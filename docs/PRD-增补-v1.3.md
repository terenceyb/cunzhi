## 0. 本轮范围与结论

本轮共 20 条修改意见，按四类归口：桌面端 4 条、移动端 4 条、两端共有 5 条、其他 2 条（其中 3.2、3.5 为复合条目，拆分为 7 个子项）。

核心变化只有三处，其余都是围绕这三处的收口：

| 变化 | 一句话说明 |
|---|---|
| **卡堆统一** | 桌面与手机共用同一套 Wallet Card Stack，卡片即详情，不再有「卡片区 + 详情区」两块 |
| **工作台宫格** | 从「列跨度 + 网格自动流」改为「自由宫格」：拖标题换位置、拖右下角无极缩放、内容随尺寸自适应 |
| **明暗模式** | 设置新增「外观」，三档：跟随系统 / 浅色 / 深色，切换即时生效、只存本机 |

## 1. 桌面端

### 1.1 人脉列表：桌面端也要叠放

**问题**：桌面端列表模式是纵向平铺的卡片流，与手机端的卡堆视觉完全两套。

**方案**：删除桌面专用的 `WalletList` 平铺实现，桌面与手机共用 `WalletStackView`；桌面居中限宽 520px，避免一张卡横跨整屏。

**实现**：`People.tsx` 的 `view === 'cards'` 分支不再按端分叉；`WalletList` 组件及其样式（`.w2-item`、`.w2-acc-*`）整体删除，减少约 60 行死代码。

**验收**：桌面上人脉列表呈现与手机一致的叠放卡堆，露出的条带能看到姓名与电话。

### 1.2 工作台：三张卡片无极缩放 + 宫格拖拽

**问题**：卡片只能按「列跨度」整数吸附改变宽度，高度固定，不能移动位置；内容不会随尺寸变化。

**方案**：

1. **默认宫格**：桌面 4 列 × 2 行，平板 2 列、手机 1 列；行高桌面 210px、手机 150px。
2. **拖拽换位**：拖卡片标题（不含按钮），卡片跟手位移，松手落到最近的格；撞位时对方自动让到最近的空位，永不允许重叠。
3. **右下角无极缩放**：拖动 `.dash-corner`，宽高连续变化、精度 0.05 格，不吸附格点；最小 1 格。
4. **内容随尺寸变化**：卡片按高度分三档密度（s / m / l），档位决定：
   - 列表条数 = 高度 × 3（提醒）、高度 × 3 / 2（待办，按分组均分）、高度 × 3（纪念日）；
   - `s` 档隐藏建议语、待办副行、底部提示；`l` 档加大行内边距。
5. **一键恢复**：右上角「恢复默认布局」重置顺序、位置、尺寸。

**实现要点**：

- 布局数据由 `Preference.dashboardLayout.cells: Record<key, {x,y,w,h}>` 存储，`x/y` 为整数格坐标，`w/h` 可为小数。
- 摆放用「绝对定位 + 百分比换算」：`left = x·(100%+gap)/cols`、`width = w·(100%+gap)/cols − gap`，因此窗口缩放不需要 JS 重算。
- `resolveCells()` 在每次渲染时校验存储值：越界、被占位、缺省都走「先上后左」的首次适配算法，保证任何脏数据都不会造成重叠。
- 拖拽时用 `translate` 跟手（不触发 left/top 过渡），落位后写回 cells 由 CSS 过渡补齐动画。

**验收**：拖标题可换位、无重叠；拖右下角可连续放大缩小；卡片变矮时内容自动减条，变高时增加；刷新后布局保持。

### 1.3 走动提醒：图标常显

**问题**：「已联系」与时钟图标只在 `:hover` 时出现，触摸板和键盘用户拿不到。

**方案**：`.reminder-actions` 的 `opacity` 由 0 改为 1，删除配套的 hover / focus-within 显示规则。

**验收**：不移动鼠标也能看到两个操作按钮。

### 1.4 待办：日期框与日历按钮贴合

**问题**：`.field` 为纵向 flex，子元素默认拉伸，`.date-field` 被撑满整行，日历按钮贴在最右侧，与文本框相距百余像素。

**方案**：`.field > .date-field { align-self: flex-start }`，日期控件宽度回归内容宽度；该修复对全站所有日期字段生效（待办、纪念日、筛选、字段编辑）。

**验收**：日历按钮紧贴文本框右缘。

## 2. 移动端

### 2.1 卡堆露出方向修正

**问题**：叠放时露出的是每张卡的下半截，只能看到公司名与上次互动，看不到是谁。

**方案**：改为「向上叠」：前卡固定在堆底、完整可见，后面的卡依次向上偏移一个 peek（46px），露出各自的**上半截**；卡片信息顺序因此重排为「姓名 / 职务 → 电话 → 标签 → 单位 / 上次互动」。

**实现**：`.w2-slot` 的 `top = spread − pos × peek`，`z-index = 100 − pos`；`spread = (显示数 − 1) × peek`，容器高度 = 卡高 + spread，过渡 400ms。

**验收**：每张露出的条带都能看到头像、姓名、完整电话与群组。

### 2.2 底部提示文字在移动端隐藏

**方案**：`@media (max-width: 767px) { .dash-foot { display: none } }`。桌面端保留，因为拖拽/快捷键只有桌面可用。

### 2.3 顶栏三个图标改为正方形

**问题**：移动端全局 `.btn { min-height: 38px }` 把 34×34 的图标按钮拉成 34×38 的长方形。

**方案**：`.topbar .btn.icon { width: 38px; height: 38px; min-height: 38px }`，同时把顶栏间距从 10px 收到 6px，三个方形按钮并排不挤占标题。

**验收**：搜索 / 速记 / 新建三枚按钮为正方形，圆角 11px。

### 2.4 卡堆头部改两行排版

**问题**：`3 天` 与两句说明挤在一行，`*天` 字号不够突出。

**方案**：头部改为左右两栏——左侧天数 30px / 650 字重（桌面 34px），右侧两行说明：第一行「距上次与 XX 联系」，第二行「共 N 位 · 点卡片换人，点最上面那张看详情」；单行超长时省略。

**验收**：天数在一行内视觉权重最高，说明文字自动换两行、不撑破容器。

## 3. 两端共有

### 3.1 卡片的层叠上下文收敛

**问题**：卡堆用 `z-index: 100 − pos` 实现层级，未建立独立层叠上下文，导致卡片盖住筛选面板、下拉菜单等浮层。

**方案**：`.w2-stack { isolation: isolate; z-index: 0 }`，卡片的高 z-index 被限制在卡堆内部，与页面其他浮层互不干扰。

### 3.2 卡面信息重构

| 子项 | 处理 |
|---|---|
| 删掉金色芯片与非接触图标 | 移除 `.w2-emv`、`.w2-nfc` 与其三层伪元素，卡面留白更干净 |
| 电话完整显示 | 删除 `maskPhone`，改为按 3-4-4 分组的美化格式（`137 0137 0003`），全量展示 |
| 排版重排 | 四行结构：信息区（头像 + 姓名 + 职务 + 群组）→ 电话 → 标签 → 单位 / 上次互动；露出的 46px 刚好容纳前两行 |
| 显示职务与标签 | 职务取字段 `custom_role`，紧跟姓名、灰阶显示；标签最多 3 个，超出省略；无标签时降级显示单位 |

### 3.3 字段管理排版

| 子项 | 处理 |
|---|---|
| 名称与类别左对齐 | 名称输入框 `margin-left: -4px` 抵消自身 4px 内边距，与下方「文本 · 使用 N 人」左缘对齐 |
| 长名不再提前截断 | 输入框宽度由 `ch` 改为 `em`（`len × em + 1.6em`）——`ch` 对中文等于半字宽，是截断过早的根因；锁定字段保留 260px 上限并省略 |
| 锁定徽标紧跟名称 | 保持 `fm-name-line` 行内流式跟随，不占固定列宽 |

### 3.4 卡片标题加大

**方案**：图标 14 → 19px，标题 13.5 → 15.5px / 650 字重，标题左侧图标颜色由三级灰提升到二级灰。

### 3.5 卡片与详情不再割裂

**问题**：移动端详情区是卡堆下方独立的一块手风琴，与「哪张卡」没有视觉绑定，用户理解为两个界面。

**方案**：点前排卡片，卡片**原地展开**——详情行（上次互动、互动记录、邮箱、标签、城市、爱好、备忘）与「打开完整名片」按钮渲染在同一张卡内部，背景、圆角、阴影延续卡面；再次点击或点「收起，回到卡堆」收回。点后面的卡则先把该卡换到前排。

**实现**：`WalletCardFace` 由 `<button>` 改为 `role="button"` 容器，允许内部嵌套按钮；展开态 `.w2-card[data-focus='true']` 隐藏底部单位行（详情里已有上次互动），高度自适应；点「打开完整名片」才进入全屏详情页。

**验收**：卡片与详情是一体的，任意一张卡都有自己的详情，不存在「共用一个详情区」。

### 4.2 外观：三档明暗模式

**方案**：设置新增「外观」分页，三张选项卡（跟随系统 / 浅色 / 深色），选中态用强调色描边 + 打勾。

**实现**：

- 偏好项 `Prefs.theme: 'system' | 'light' | 'dark'`，默认 `system`，存本机 localStorage（不写入数据包，避免跨设备互相干扰）。
- `<ThemeSync />` 挂载时与系统主题变化时写 `document.documentElement.dataset.theme`，CSS 只需一套 `html[data-theme='dark']` 变量覆盖。
- 深色调色板重定义 20 个语义变量（背景、三级表面、三级文字、描边、四色语义、三级阴影、玻璃层、反色前景），组件层零改动。
- `color-scheme` 同步切换，原生控件（滚动条、日期选择器、select）跟随变深。

**验收**：三档切换即时生效、刷新保持；深色下正文对比度 ≥ 7:1，按钮、开关、输入框、浮层均可读。

## 6. 已知取舍

1. **卡堆一次摊开 6 张**：再多人用「后面还有 N 位 · 翻下一叠」轮转，避免 14 张叠成一条没有信息的深色带。这是可读性与「一次看全部」之间的取舍。
2. **移动端提醒行隐藏「上次互动 X」与建议语**：窄屏还要放下逾期徽标与两个按钮，三行会让每张卡只能容纳 3 人；桌面端完整保留。
3. **深色模式不跟随数据包**：主题属于设备偏好，换个设备看到的是那台设备的设置，与「数据可搬运」的定位一致。
4. **宫格最小 1 格**：不开放无限制缩小，避免卡片被缩到读不出标题。

## 7. 数据结构增量

```ts
// Prefs（本机偏好，localStorage: cunzhi.prefs.v1）
interface Prefs {
  // v1.3 变更：widths: Record<string, number> → cells
  dashboardLayout: {
    order: string[]
    collapsed: string[]
    cells: Record<string, { x: number; y: number; w: number; h: number }>
  }
  theme: 'system' | 'light' | 'dark'  // v1.3 新增
}
```

**迁移**：旧版本只有 `widths` 时，`cells` 缺失 → 由 `DEFAULT_PREFS.dashboardLayout.cells` 兜底（提醒 2×2、待办 1×2、纪念日 1×2），用户无需手动迁移；数据包格式（`.czdb`）无任何字段变更，向后兼容。
