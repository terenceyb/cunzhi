> 适用版本：存知 Web v1.4　|　文档性质：第七轮迭代增补（增量需求，合并进 v1.3 主文档）
> 迭代主题：**布局权责归位、待办中心、详情页重排**
> 交付状态：全部条目已实现并通过构建与浏览器实跑校验

## 0. 本轮范围与结论

本轮 17 条意见（3.2 为复合条目，拆出 6 个子项，实际 22 个改动点），归口四类：桌面 3 条、移动 3 条、两端共有 4 条、其他 4 条。

三条主线：

| 主线 | 说明 |
|---|---|
| **布局权责归位** | 桌面保留「拖拽换位」、撤掉无极缩放；移动端彻底退出宫格，改固定顺序流式排布，顺序交给设置页 |
| **待办中心** | 待办从「首页一张卡」升级为可分类管理的独立界面，并首次引入回收站（软删除） |
| **详情页重排** | 字段顺序与设置联动、空字段行高压缩、时间线只读、头部信息密度重做 |

一个根因修复值得单独记：**空字段行高度异常**并非设计值过大，而是行元素用了 `empty` 这个类名，被全局空状态样式（`.empty { display:flex; flex-direction:column; align-items:center }`）命中，导致每行被拉成两行、高 134px 且内容居中。改名为 `is-empty` 后行高回落到 30px。

## 1. 电脑端

### 1.1 工作台：撤掉无极缩放，只保留换位

**变更**：删除右下角 `dash-corner` 手柄与整套 `startResize` 逻辑；卡片尺寸回归默认（提醒 2×2、待办 1×2、纪念日 1×2）。

**换位动效**：不再「松手才重排」，改为拖动过程中实时让位——

1. 指针移动时按列宽 / 行高把位移折算成目标格；
2. 目标格若与别的卡重叠，被撞的卡立即按「先上后左」找最近空位，并写进实时状态；
3. 被拖的卡继续用 `translate` 跟手（不参与 left/top 过渡，避免抖动）；
4. 松手才落库（localStorage），整盘卡片以 280ms `cubic-bezier(.16,1,.3,1)` 收拢到位。

**验收**：拖动途中其他卡片已让开、无空隙重叠；松手后位置持久化，刷新保持。

### 1.2 人脉列表（桌面）

| 子项 | 处理 |
|---|---|
| 1.2.1 露出高度 | 桌面 peek 46 → **64px**，卡片高度 154 → **176px**；移动端维持 46 / 122 |
| 1.2.2 全部叠放 | 桌面不再分页，一次渲染全部卡片，整页滚动即可看全；「后面还有 N 位 · 翻下一叠」只在移动端保留（窄屏确实放不下 14 张） |
| 1.2.3 头部文案 | 删除「点卡片换人，点最上面那张看详情」，改为「距上次与 XX 联系 / 共 N 位人脉 · 按联系紧迫度排序」，天数 34px/650 作为视觉锚点 |

**实现**：`WalletStackView` 增加 `wide` 判定（700px 断点以上），peek、折叠上限、分页按钮三处随端切换；卡序安全过滤（`order.filter(i => i < rows.length)`）顺带修掉下节的崩溃。

### 1.3 / 1.4（上一轮遗留项）

走动提醒「已联系 / 时钟」常显、待办日期框与日历按钮贴合，本轮回归通过，未再改动。

## 2. 移动端

### 2.1 工作台：退出宫格，顺序交给设置

**变更**：

- 移动端不再渲染宫格容器（`.dash-board`），改用 `.dash-flow` 纵向流式排布：卡片自然高度、可折叠、无拖拽、无缩放。

## 3. 两端共有

### 3.1 待办中心

**入口**：工作台「待办事项」卡片标题可点（标题右侧箭头 hover 出现），点开进入待办中心。

**结构**：五个分类页签，均带实时计数——

| 页签 | 口径 |
|---|---|
| 全部 | 未进回收站的全部待办，未完成在前、按截止日升序 |
| 进行中 | 未完成 |
| 逾期 | 未完成且已过截止日 |
| 已完成 | 勾选完成，按完成时间倒序 |
| 回收站 | 已删除，按删除时间倒序 |

**回收站机制**：`deleteTodo` 从「物理删除」改为软删除（写 `deletedAt`），新增 `restoreTodo` / `purgeTodo`。数据包结构向后兼容（新字段可选），旧包打开后回收站为空。所有消费方（首页分桶、人脉详情、统计）统一过滤 `deletedAt`。

**行内操作**：勾选完成（同步互动记录的确认逻辑沿用原有确认弹窗）、删除到回收站、回收站内恢复 / 彻底删除（彻底删除不可撤销）。

### 3.2 人脉详情页

#### 3.2.1 字段顺序与设置联动

原先详情页把字段按 `group` 拆成「基础信息 / 联系方式 / 自定义字段」三段，设置里的排序只在段内生效。现改为**单一有序列表**：过滤可见、未禁用、非时间线字段后，直接按 `sortOrder` 渲染，姓名固定第一行。设置里拖到最上面的字段，详情页就在最上面。

#### 3.2.2 空字段高度

根因见第 0 节（类名冲突）。修复后：空字段行 30px、与普通行（40px）同一节奏，标签与占位同排，不再居中换行。

#### 3.2.3 记录互动改为弹窗

- 右上角「记录互动」按钮由「滚动定位到时间线输入框」改为打开 `InteractionDialog`，与工作台走动提醒里的「已联系」**同一个组件、同一套字段**（人 + 方式 + 内容 → 写入时间线）。
- 详情页互动时间线下方的录入区（方式胶囊、输入框、记录按钮）整段删除，时间线变为**只读呈现**：只显示「记录互动」与「已联系」两条入口写进来的内容，保留置顶、删除、按类型筛选、多选删除。

#### 3.2.4「+ 更多方式」未生效

原因：新增的字段值是空的，而详情页默认不显示空字段，于是字段加成功了却看不见。

处理：新增后把该 key 放进 `pinnedKeys` 强制显示，并置 `autoEditKey` 让该行直接进入编辑态，用户落地即可填写。

顺带修掉一个可达性缺陷：`Menu` 在 `onClickCapture` 阶段拦截了冒泡，导致键盘 Enter 打不开菜单（鼠标因 `pointerdown` 先行仍然可用）；已补 `onKeyDown` 放行。

#### 3.2.5 关系备忘可输入性

原来「添加」按钮错绑成「切换显示空字段」，且未填写时只是一行灰字，看不出可写。现在：

- 未填写：虚线框 + 铅笔图标 + 引导文案「怎么写、在哪认识、聊过什么、下次可以聊什么 —— 点这里写下来」，整块可点；
- 已填写：实线框展示正文，点击进入编辑；
- 标题右侧「添加 / 编辑」按钮直接唤起编辑态。

#### 3.2.6 头部重排

原结构：头像 + 姓名 + 单位城市 + 群组标签胶囊 + 三个 mini-stat 块，纵向堆叠约 150px。

新结构（约 86px）：

```
[头像 44]  姓名  群组胶囊  标签×2                     [记录互动] [⋯]
           单位 · 城市 ● 上次互动 3 天前 ● 3 条记录 ● ◔ 完整度 87%
```

- 完整度由 30px 圆环改为 16px 微环，与「上次互动 / 记录数」同排；
- 三个 mini-stat 区块整体删除，信息改为一行点分隔；
- 窄屏自动换行，标签胶囊隐藏，只保留群组。

### 3.3 智能视图切换白屏

**现象**：先点「待补全信息」再点「最近添加」，整页空白。

**根因**：`WalletStackView` 用下标数组 `order` 记录卡序；切换视图后行数从 6 变成 1，`order` 仍持有越界下标，渲染时 `rows[idx]` 为 `undefined`，`buildPersonMeta` 读 `.fields` 抛错，React 整树卸载 → 白屏。

**修复**：渲染前过滤越界下标（`order.filter(i => i < rows.length)`），空则回退为自然序。已用自动化脚本回归验证：切换后正常渲染且无控制台错误。

### 3.4 工作台主题色

「设置 → 外观」新增**工作台主题色**：石墨 / 暖沙 / 松绿 / 远海 / 梅紫。

实现：`prefs.dashAccent` 写到 `.dash-page[data-accent]`，只改一个 CSS 变量 `--dash-tint`，作用于三张卡片顶部的 3px 渐变细线、标题图标、标题 hover 与箭头浮现。控件为色点 + 名称的胶囊，选中态带描边与光晕。

### 4.3 折叠按钮

去掉 `.btn` 自带的 1px 描边与底色，改为纯图标按钮：默认三级灰，hover 出现 `--surface-2` 圆角底色与一级文字色；折叠态图标仍走 `IconSwap` 的 150ms 交换。

### 4.4 全局对比度

| 令牌 | 浅色（原 → 新） | 深色（原 → 新） |
|---|---|---|
| `--text-2` | `#565f6b` → `#48515d` | `#a7b0bc` → `#b4bcc7` |
| `--text-3` | `#8b95a1` → `#6b7583` | `#7a8492` → `#8d97a5` |

移动端再提一档（`--text-2 #3f4853` / `--text-3 #5d6673`，深色对应 `#c3cad3` / `#9aa4b1`），通过 `@media (max-width: 767px)` 内的 `:root` 覆盖实现——户外强光下手持设备最容易吃灰阶。

对比度：浅色正文 `--text` 对 `--surface` 约 16:1，`--text-2` 约 8.4:1，`--text-3` 约 5.6:1，均高于 WCAG AA 的 4.5:1。

## 6. 已知取舍

1. **桌面卡堆不翻页**：一次渲染全部卡片，几百人时首屏 DOM 略重（每卡约 8 个节点），1500 人以内实测流畅；再往上建议接虚拟滚动，本轮不做。
2. **桌面卡堆仍是「向上叠」**：只露出上半截时，前卡只能在堆底、后面的卡向上偏移，这是几何决定的唯一解；因此视觉上从下往上读即对应紧迫度从高到低。
3. **移动端只播 6 张**：窄屏放不下 14 张，保留「翻下一叠」轮转，避免叠成一条读不出信息的深色带。
4. **彻底删除不可撤销**：回收站内二次确认后才物理删除，不提供快照回滚（字段变更另有快照，待办没有）。
5. **移动端顺序与桌面顺序解耦**：两套独立偏好，换端不会互相覆盖。

## 7. 数据结构增量

```ts
// Todo：新增软删除标记，回收站据此过滤
interface Todo {
  deletedAt?: string | null   // v1.4 新增
}

// Prefs（本机偏好，localStorage: cunzhi.prefs.v1）
interface Prefs {
  dashAccent: 'slate' | 'sand' | 'forest' | 'ocean' | 'plum'   // v1.4 新增
  dashMobileOrder: string[]                                     // v1.4 新增，默认 ['todos','reminders','anniversaries']
}

// Store 行为变更
deleteTodo(id)   // 物理删除 → 写 deletedAt
restoreTodo(id)  // v1.4 新增
purgeTodo(id)    // v1.4 新增，物理删除
```

**迁移**：`Prefs` 走 `{...DEFAULT_PREFS, ...parsed}` 深合并兜底，老用户首次打开即获得默认主题色与移动端顺序；`.czdb` 数据包仅多一个可选字段，旧版本打开新版包时忽略该字段，不破坏格式。
