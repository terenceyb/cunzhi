> 文档类型：产品需求增补（Change Request 汇总）
> 基线版本：PRD V1.0（汇总定稿版）
> 适用范围：Web 端（桌面 ≥1200px、平板 768–1199px、手机 <768px）
> 编写依据：试用反馈 22 条，逐条转化为可验收需求

## 0. 增补总览

本次增补不改变 PRD V1.0 的产品定位与核心模型（本地优先、三 Tab、14 默认字段、走动提醒、关系网只读）。改动集中在三处：

1. **交互一致性**：折叠侧栏、字段行编辑、菜单层级、焦点管理——把「能点」改成「点得对」。
2. **移动端可用性**：设置页导航、弹窗比例、智能视图入口、视图收敛。
3. **数据自主权延伸**：标签/群组自定义、从零开始不预置业务数据、礼物型互动记录。

## 1. 桌面端专属

### D-01 折叠侧栏导航项拥挤

**现状**：点击侧栏收起按钮后，「工作台 / 人脉 / 字段管理 / 设置」等按钮图标与背景块几乎重合，文字虽隐藏但按钮内边距未同步收缩，视觉上挤成一团。

**目标**：折叠态是「一列图标」，每个按钮 40×40，图标居中，背景高亮为圆角方块，与展开态保持同一行高节奏。

**规则**

- 折叠态宽度 64px（原 56px），按钮改为 40×40 居中，左右内边距 12px。
- 折叠态隐藏文字与计数徽标，但保留 hover tooltip 显示名称。
- 折叠态品牌区只显示 Logo 方块，隐藏「存知」字样。
- 折叠状态持久化到 `prefs.sidebarCollapsed`。

**验收**：折叠后每个导航按钮水平垂直居中，任意两个按钮不粘连；展开/折叠切换无跳动。

## 2. 移动端专属

### M-01 设置页改为「列表 → 详情」两级导航

**现状**：设置页顶部九个标签（我的信息 … 隐私与安全）横向排列，移动端需左右滑动才能看到后面的标签，且滑动与页面滚动冲突。

**目标**：移动端点击「设置」进入**设置索引页**，纵向列出九项（图标 + 名称 + 一行说明 + 右箭头），点击任一项进入该分页；分页顶部提供返回箭头。

**规则**

- 断点：`max-width: 767px` 生效。
- 索引页是「入口」，不承担任何编辑能力。
- 进入分页后保持 `settingsTab`，返回索引页不重置。
- 桌面端维持左侧竖排导航 + 右侧内容（不变）。
- 从其他位置深链到某分页（如详情页「管理字段」）时，直接进入该分页，返回键回到索引页。

**验收**：移动端设置页无横向滚动；九个入口一屏内可见（可纵向滚动）；点进任一页可返回。

### M-02 搜索弹窗比例

**现状**：移动端搜索面板接近全屏高度，结果只有 1–2 条时下方大片留白。

**目标**：面板贴顶显示，最大高度 70vh，内容自适应；结果为空或无匹配时高度收缩到内容高度。

**规则**

- `max-height: min(70vh, 560px)`，面板内部滚动。
- 顶部与状态栏间距 8px，左右 8px。
- 结果列表最多 6 条后滚动。

**验收**：1 条结果时面板高度 ≈ 输入框 + 1 行；8 条结果时面板 ≤70vh 且内部可滚。

### M-03 新建人脉弹窗高度

**现状**：表单弹窗高度按内容撑开，超出移动端可视区域，底部按钮不可达。

**目标**：任何弹窗在移动端不得超过视口高度，头部与底部按钮固定，中间滚动。

**规则**

- 弹窗容器：`height: calc(100dvh - 24px)`，`max-height` 同上，`overflow: hidden`。
- 头部 52px 固定，底部操作条固定（含安全区内边距），`modal-body` 滚动。
- 键盘弹起时（`visualViewport` 高度变化）同步收缩。

**验收**：iPhone 尺寸（390×844）下打开新建表单，底部「保存」始终可见可点；滚动到最底部内容不被遮挡。

### M-04 移动端智能视图入口

**现状**：智能视图只在左侧栏渲染，而侧栏在移动端隐藏，导致移动端完全无法使用智能视图。

**目标**：人脉页顶部新增**视图胶囊条**（横向可滑动），列出「全部人脉 + 用户创建的智能视图」，点击即应用筛选。

**规则**

- 仅在 `max-width: 767px` 显示，桌面端不重复展示。
- 当前生效的视图高亮，并显示命中人数。
- 点击后同步 `activeSmartViewId` 与筛选条件，与桌面侧栏行为一致。

**验收**：移动端人脉页可看到全部智能视图并切换；切换后列表人数与筛选 chips 同步。

### M-05 移动端视图收敛为宫格

**现状**：移动端同时提供「列表（卡片流）/ 宫格 / 表格 / 关系网」四种视图，其中列表与宫格视觉差异极小（都是单列卡片）。

**目标**：移动端只保留「宫格」与「关系网」，列表/表格入口隐藏；桌面端四种全部保留。

**规则**

- 移动端默认视图强制为 `grid`；若上次停留的是 `cards`/`table`，进入移动端时回落为 `grid`。
- 桌面端切回时恢复用户上次选择。

**验收**：390px 下视图切换只剩两个按钮；1280px 下四个按钮齐全。

## 3. 双端共有

### C-01 字段行编辑与行内按钮冲突

**现状**：详情页「点击字段行即编辑」，联系方式字段右侧的「电话 / 短信 / 复制」三个按钮位于同一行，点击按钮同时触发行编辑，弹出编辑态打断操作。

**目标**：行内操作按钮优先，点击按钮只执行按钮行为，不进入编辑。

**规则**

- 行点击处理器判断事件源：命中 `a`、`button`、`[data-no-edit]` 时直接返回。
- 电话/短信/复制按钮增加 `data-no-edit` 语义标记，双击不进入编辑。
- 行尾「铅笔」图标保留，点击铅笔始终进入编辑（明确入口）。

**验收**：点击「复制」只复制号码并提示；点击行空白处进入编辑。

### C-02 「记录联系」按钮语义修正

**现状**：详情页右上角是「对号」图标，点击直接写入一条联系记录，用户误以为是「保存/确认」，且不符合「记录应先发生再录入」的现实逻辑。

**目标**：改为「记录联系」图标（对话+笔），点击后**打开并聚焦内联速记输入**，由用户写下内容后提交，再写入互动时间线。

**规则**

- 图标换为 `MessageSquarePlus`，`aria-label="记录一次联系"`。
- 点击 → 滚动到「互动时间线」输入区 → 聚焦输入框 → 通道默认「微信」。
- 保留快捷入口：在输入框内 `Enter` 提交。
- 若用户只想要「一键已联系」，在输入区右侧保留「仅标记已联系」文字按钮。

**验收**：点击头部按钮后光标落在输入框；输入内容回车后时间线出现记录；不输入内容不会产生空记录。

### C-03 头像上传后仍显示文字

**现状**：在「我的名片」上传头像后，头像位仍显示姓名首字。

**目标**：上传成功后立即显示图片，刷新后仍在。

**规则**

- 写入 `settings.profile.avatarAttachmentId` 的同时，必须把附件实体写入 `attachments`。
- 头像读取链路：`attachments[id].thumbnail ?? attachments[id].data`。
- 上传中显示「处理中」，失败给出原因（格式/体积）。

**验收**：上传 PNG/JPG 后 1s 内头像变为图片；刷新页面后保持。

### C-04 标签与群组支持自定义

**现状**：标签、群组只能从预置列表中选择，无法在录入过程中新建。

**目标**：在新建/编辑人脉表单与详情页字段编辑中，均可「新建标签」「新建群组」，并即时出现在选项中。

**规则**

- 标签选择器底部固定「+ 新建标签」，输入名称回车即创建并选中。
- 群组选择器同理，新建时可选颜色（沿用现有 7 色板）。
- 新建的群组/标签进入「设置 → 字段管理」可编辑、删除（已有能力）。
- 重名不重复创建，直接选中已存在项。

**验收**：表单内新建「邻居」群组后无需保存表单即可选中；保存后详情页标签展示正确。

### C-05 走动提醒点击进入详情

**现状**：工作台「走动提醒」点击整行无反应，用户无法从提醒直接进入该人脉详情。

**目标**：点击提醒条目任意空白区域，跳转到人脉页并打开该联系人详情。

**规则**

- `openPerson()` 需同时切换路由到 `people` 并打开详情（跨页跳转）。
- 条目内「已联系」按钮、「稍后提醒」菜单、多选框点击不触发跳转。
- 多选模式下点击为选中，不跳转。

**验收**：从工作台点击任一条提醒 → 落地人脉页且右侧详情为该联系人；点「已联系」只更新状态不跳转。

### C-06 待办关联人脉可搜索

**现状**：新建待办时「关联人脉」是原生下拉，人多时难以定位。

**目标**：改为可搜索选择器（拼音 + 姓名），支持键盘上下选择、回车确认、可清空。

**规则**

- 输入即过滤；无匹配时显示「无结果」。
- 已选中显示为胶囊，可移除。
- 允许不关联任何人脉（全局待办）。

**验收**：输入 `zs` 可命中「张三」；回车选中后关闭面板；保存后待办正确归属。

### C-07 速记：类型按钮间距 + 礼物模式

**现状**：速记弹窗内「普通备注 / 电话沟通 / 见面 / 微信沟通 / 邮件」五个按钮紧贴，无法区分点击区域；且无法记录送礼往来。

**目标**：按钮等宽等距、可换行；新增「礼物」类型，可记录礼物内容与价值。

**规则**

- 类型按钮改为分段式胶囊组：`gap: 8px`、`padding: 6px 12px`、最小高度 30px，窄屏自动换行。
- 新增类型「礼物」，选中后出现两个字段：
  - 礼物内容（文本，必填）
  - 价值（数字，可选，单位元）
- 写入时间线的文本格式：`礼物：<内容>（价值 ¥<金额>）`，未填价值则为 `礼物：<内容>`。
- 时间线类型新增 `gift`，图标为礼物盒，可选筛选。

**验收**：五个类型按钮互不粘连；选「礼物」后可填内容与价值；保存后时间线显示礼物条目且筛选「礼物」可命中。

### C-08 日期选择统一「年-月-日」

**现状**：原生日期控件占位显示 `mm/dd/yyyy` 或 `yyyy-mm-日`，中英夹杂；不同浏览器显示不一致。

**目标**：全站日期输入统一为「年-月-日」语义，占位与已填值格式一致。

**规则**

- 日期输入改为「文本输入 + 日历按钮」组合：文本框占位 `年-月-日`，输入自动补分隔符，失焦校验合法性。
- 日历按钮唤起原生选择器（隐藏的 date input），选中后回填 `YYYY-MM-DD`。
- 展示层统一 `YYYY年M月D日`（列表/详情）与 `YYYY-MM-DD`（表单）。

**验收**：表单日期框占位为「年-月-日」；输入 `2026-03-05` 有效，输入 `2026-13-01` 提示无效；日历选择后回填正确。

### C-09 从零开始不预置业务数据

**现状**：即使选择「从零开始」，仍加载了 6 个默认群组与若干默认标签，与「数据是用户的」相悖。

**目标**：从零开始 = 空库：0 人、0 标签、0 群组、0 待办、0 纪念日；仅保留 14 个默认字段定义与 3 个系统智能视图。

**规则**

- `createDefaultGroups()` 仅用于演示数据；从零开始时 `groups = []`、`tags = []`。
- 首次进入人脉页的空态文案提示「可先建一个群组（如：同事、客户）来分类」。空态提供「新建群组」快捷入口。
- 演示数据仍保留完整标签与群组，用于体验。

**验收**：从零开始后设置页群组/标签为空；人脉表单群组下拉显示「未设置 + 新建群组」。

### C-10 合并「字段管理」与「设置」入口

**现状**：侧栏「系统」分组下并列「字段管理」「设置」，其中「设置」默认落在「数据包管理」页，两个入口语义重叠，用户难以建立稳定心智。

**目标**：系统分组只保留一个「设置」入口，点击进入设置索引（桌面为左侧导航第一项，移动为索引列表）；字段管理作为设置的子页。

**规则**

- 删除侧栏「系统」下的「字段管理」按钮。
- 「设置」入口高亮条件为 `route === 'settings'`，不再区分 tab。
- 设置页内「字段管理」保持原位（第二个子页）。
- 深链 `navigate('settings', { tab: 'fields' })` 仍然有效（详情页「管理字段」会用到）。

**验收**：侧栏系统分组只有一个按钮；从详情页点「管理字段」可直达字段管理页。

### C-11 配置列菜单被遮挡

**现状**：人脉表格「配置列」下拉菜单渲染在表格容器内部，被后续行与容器裁切，按钮点不到。

**目标**：所有下拉菜单脱离容器层级，浮于最上层，且不超出视口。

**规则**

- 菜单使用 Portal 渲染到 `body`，`position: fixed`，`z-index` 高于弹窗遮罩以外的所有内容。
- 依据触发元素位置计算坐标，右对齐；下方空间不足时自动向上翻转；左右边缘留 8px 安全距。
- 点击外部、Esc、选中任意项后关闭。

**验收**：表格滚动到任意位置点「配置列」，菜单完整可见可点；靠近窗口底部时菜单向上展开。

### C-12 速记输入时光标被抢

**现状**：在速记输入框打字，光标会跳到右上角关闭按钮，导致连续输入中断。

**根因**：弹窗的自动聚焦副作用依赖了每次渲染都变化的 `onClose` 回调，输入触发重渲染 → 副作用重跑 → 焦点被重置到 DOM 中第一个可聚焦元素（头部的关闭按钮）。

**目标**：弹窗打开时只聚焦一次，后续输入不被打断。

**规则**

- 聚焦副作用只依赖 `open`，`onClose` 通过 ref 引用。
- 聚焦优先级：`[data-autofocus]` → `textarea` → `input` → 第一个可聚焦元素；**排除**头部关闭按钮。
- Tab 焦点循环逻辑保留。

**验收**：在速记框连续输入 20 个字符，光标始终在输入框末尾；Esc 可关闭。

### C-13 字段管理列表对齐与操作位

**现状**：①「必填」「可见」两列开关在不同行左右错位；②锁定字段（姓名/电话/互动记录/引荐人）缺少禁用与删除按钮，导致行尾参差；③「禁用字段」用的是对号图标，易被误认为「确认」。

**目标**：四列网格对齐；所有行都有完整的三个操作位；锁定行的禁用/删除为浅灰不可点；禁用图标改为「禁止」语义。

**规则**

- 行布局：`grid-template-columns: 20px minmax(0,1fr) 168px 96px`，四列固定。
- 必填/可见：每组为「标签 28px + 开关」，右对齐，垂直居中对齐。
- 操作区固定 3 个 24×24 位：配置（Info）、禁用/启用（Ban / RotateCcw）、删除（Trash2）。
- 锁定字段的禁用与删除按钮：`disabled`，颜色 `--text-4`，鼠标指针 `not-allowed`，`title` 说明「锁定字段不可删除/禁用」。
- 禁用状态图标统一为 `Ban`（斜杠圆），启用态为 `RotateCcw`。

**验收**：任意滚动位置，「必填」「可见」两列开关在同一条竖线上；锁定行的三个按钮都存在且不可点；禁用图标不再是与「确认」相关的对号。

### C-14 移除常驻 IndexedDB 警告

**现状**：页面顶部常驻「IndexedDB 可能被浏览器清理…」提示条，长期占用首屏空间，且重复提醒已让用户忽略。

**目标**：改为「进入时一次性提醒」：仅在本次会话首次进入且从未备份时，用一条 6 秒自动消失的 Toast 提示，附「去备份」操作；关闭后本次会话不再出现。

**规则**

- 移除 `StatusBanners` 中的该分支。
- 首次进入（`prefs.lastBackupAt` 为空且有人脉）弹 Toast：`数据存在浏览器里，建议导出一次数据包做兜底` + 操作按钮。
- 同一会话（sessionStorage 标记）只出现一次。
- 数据包/只读/写盘失败等**状态类**提示保留（它们代表真实异常）。

**验收**：刷新页面，顶部不再有黄色/蓝色提示条；首次进入右下角出现一次可操作的 Toast，6s 后消失，再切页不再出现。

## 4. 视觉与品牌

### V-01 视觉基准

参考对象：`transitions.dev`（动效规范）、`60fps.design`（性能与动效质量）、现代 SaaS 工作台（Linear / Notion 类）的信息密度与留白。

**规则**

- 动效统一：`--ease-out: cubic-bezier(0.16,1,0.3,1)`，进入 160–200ms、退出 120ms；仅对 `transform` / `opacity` 做动画，避免布局抖动。
- 列表项 hover 用背景色渐变，不做位移；弹层进入用 `scale(0.98) → 1` + `opacity`。
- 尊重 `prefers-reduced-motion`（已实现，保留）。
- 焦点态统一 2px accent 外环，键盘可见。
- 移动端触控目标 ≥ 40×40。

**验收**：所有弹层/菜单/Toast 进入动画一致；无肉眼可见掉帧；减少动效模式下无动画。

### V-02 品牌 Logo

**现状**：站点图标为临时生成的关系网图形，侧栏品牌块为「存」字方块。

**目标**：设计正式 Logo：以「存」的语义（关系存档）为内核，用「节点 + 连结 + 圆」表达人脉网络，形成可缩放的单一图形标记。

**规则**

- 主标记：深墨底（#131619）圆角方，内部白色节点与连线构成抽象「存」字骨架，强调点位于右下。
- 提供 192×192、512×512 PNG（PWA）、`favicon.svg`（矢量）与 `manifest` 引用。
- 侧栏品牌块、欢迎页、锁屏使用同一标记。

**验收**：浏览器标签页显示新图标；PWA 安装后桌面图标为新 Logo；192/512 尺寸下清晰无锯齿。
